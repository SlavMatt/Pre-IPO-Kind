Pre-IPO 交易阶段后端说明
1. Pre-IPO 概述
1.1 概述

Pre-IPO 永续合约允许用户在目标公司正式上市前进行交易。合约与平台现有 TradFi Perp 共享同一 perp 账户，使用 USDC 作为保证金和结算资产，采用 7×24 小时连续交易模式。

  • 保证金：USDC
  • 合约类型：永续
  • 交易时间：7×24 小时；与普通 TradFi Perp 不同，Pre-IPO 阶段不受现实市场开收盘时间限制，但不同阶段的风险等级和交易限制不同
  • 价格来源：基于 OTC 场外估值；IPO 后逐步融合至真实市场价格（blend_alpha 0→1）

Pre-IPO 阶段结束的标志是开发将 symbol_type 由 PRE_IPO 切换为对应 country_stock 类型（如 US_STOCK），此后合约按普通 TradFi Perp 规则运行。

1.2 上市路径类型

不同的上市路径对应不同的前端弹窗文案和（部分情况下）不同的 State 逻辑。当前后端字段 listing_type 用于标识路径类型。

listing_type路径名称SEC 文件是否 Rebase特殊节点本期支持
IPO传统 IPOS-1是无✓
DLDirect ListingS-1否无（文案不同）待扩展
SPACSPAC 合并S-4否股东投票、终止路径待扩展
Direct Listing 与 IPO 使用相同 State 逻辑，仅需切换弹窗描述文案；SPAC 需额外增加股东投票 State 和合约终止路径，本期暂不支持。
2. TradFi 品类归属与交易时段
2.1 TradFi 品类定义

除 Crypto Perp 外，平台增设 TradFi Perp 类型，并细分多个子类型。Pre-IPO 合约属于股票 · 美股个股子类型的特殊前置阶段，上市后自动归入该子类型的常规规则。

  • 不同子类型遵循不同的开收盘、冬夏令时、节假日规则
  • 本期只针对子类型配置 IANA 时区，不针对具体交易对单独配置

2.2 Pre-IPO 阶段交易时段

Pre-IPO 阶段不受现实市场开收盘时间限制，采用 7×24 连续交易，但不同 State 的流动性和交易限制不同。以下为 Pre-IPO 专属时段定义：

交易时段类型适用 State时间名称流动性交易限制
Pre-IPO 倒计时State 1 – 47×24（连续）pre-ipo中流动性正常交易
Pre-ListingState 57×24（约 2 天窗口）pre-listing低流动性Reduce-Only
Market MergingState 6开市后至开发手动切换market-merging低流动性Reduce-Only
Pre-IPO 阶段不配置 IANA 时区，交易时段与现实市场时间无关。State 5 / State 6 的 Reduce-Only 由系统根据 ipo_time 和 market_open_time 自动触发。

3. 核心字段配置

以下字段决定 Pre-IPO 弹窗的所有状态流转。前端实时读取这些字段计算当前 State，无本地缓存。

字段名类型说明写入方式
is_pre_ipoBoolean 是否处于 Pre-IPO 阶段。为 true 时前端展示弹窗入口标签及所有 Pre-IPO UI。 开发手动
listing_typeString 上市路径。取值：IPO / DL / SPAC。决定前端弹窗文案和 State 逻辑分支。 开发手动
ipo_timeTimestamp (UTC) 预计 IPO / 上市发生时间。路演开始时填入软确认日期；424B4 发布后如有变动需更新。未填写时弹窗展示 State 1（TBD）。 开发手动
market_open_timeTimestamp (UTC) IPO 后正式开市时间，通常为 IPO 日期后约 2 个工作日的 09:30 ET。触发 State 5 → State 6 的切换节点。 开发手动
symbol_typeString 合约子类型。Pre-IPO 阶段为 PRE_IPO；IPO Merge 完成后切换为 US_STOCK 或 KR_STOCK，前端据此隐藏所有 Pre-IPO 标签，合约进入普通 TradFi Perp 逻辑。 开发手动
is_reduce_onlyBoolean 当前是否为只减仓模式。State 5 / State 6 期间为 true，用户无法开新仓。可由系统自动触发，也可由管理员开关手动控制。 系统自动 / 开关
4. State 判断逻辑
4.1 各 State 定义

前端依据 current_time、ipo_time、market_open_time 三个时间戳实时计算当前 State。共 6 个 State，按时间顺序排列如下：

State触发条件倒计时格式弹窗高亮卡交易限制
State 1 ipo_time 未配置（null / 空） — Pre-IPO · To Be Disclosed 正常交易
State 2 current < ipo_time 且剩余 > 31 天 X Mon X Days Pre-IPO · Est. IPO Date 倒计时 正常交易
State 3 current < ipo_time 且 24h < 剩余 ≤ 31 天 X Days Pre-IPO · Est. IPO Date 倒计时 正常交易
State 4 current < ipo_time 且剩余 ≤ 24h HH:MM:SS Pre-IPO · Est. IPO Date 倒计时 正常交易
State 5 ipo_time < current < market_open_time — Pre-Listing · Market Opening 倒计时 Reduce-Only
State 6 current > market_open_time 且 symbol_type = PRE_IPO — Market Merging Phase · Market Opening 历史日期 Reduce-Only

6. ipo_time 数据来源
6.1 数据来源与确定程度

IPO 日期不是在 S-1 提交时就已确定，而是分阶段浮现。以下为各节点的数据来源和可用性评估：

时间节点来源确定程度建议使用
路演开始
IPO 前 1～2 周		 Bloomberg / Reuters / CNBC 路演报道；承销商路演材料 软确认，约 90% 不变 ✓ 可填入 ipo_time，覆盖 State 2 / State 3 倒计时展示
424B4 提交
IPO 前一晚		 SEC EDGAR 最终招股书；精确日期 + 发行价同时披露 硬确认，100% △ 最准，但此时距 IPO 不足 24h，弹窗已进入 State 4

6.2 日期变更处理（约 10% 概率）

公司可能因市场情况、监管审查或承销商建议，在路演后调整 IPO 日期（推迟或提前）。此时需手动更新 ipo_time，前端状态将自动重算。

第 1 步
监听 SEC EDGAR 的 S-1/A 修订或 NASDAQ / NYSE 公告，发现日期变动后第一时间更新后台 ipo_time 字段。
第 2 步
前端倒计时基于 ipo_time 实时计算，更新后弹窗状态自动跳转——若新日期更远则从 State 4 退回 State 3 / 2；若更近则加速进入 State 4。
第 3 步
日期变更属于高风险操作，建议同步在平台向用户发出公告，避免因倒计时突变引发误操作。
7. 非活跃阶段开仓限制
7.1 Reduce-Only 自动触发条件

当 is_pre_ipo = true 且满足以下任一条件时，系统自动将该合约设为 Reduce-Only，用户无法开新仓，仅允许平仓操作：

  • State 5：ipo_time < current_time < market_open_time（Pre-Listing 窗口，约 2 天）
  • State 6：current_time > market_open_time 且 symbol_type = PRE_IPO（Merging 阶段）
7.2 管理员手动开关

在自动触发之外，管理员可通过以下开关手动干预。所有开关均需配置生效时间段（开始时间 – 结束时间），仅影响 open order，平仓的 reduce 单不受限制。

开关类型影响范围适用场景
全局 Reduce-Only 开关 所有 TradFi 合约 极端市场情况下对整个 TradFi 品类统一收紧
单交易对 Reduce-Only 开关 指定合约（如 SPCX-PERP） Pre-IPO 场景优先使用，避免影响其他正常合约
8. 手动操作节点时序

以下节点均需开发人员在确认现实状态后手动触发，系统不自动执行，目的是避免数据延迟造成错误切换。

操作顺序触发时机操作内容前端变化
① 填入 ipo_time 路演开始时（IPO 前 1～2 周） 将路演公布的 IPO 日期（UTC）填入 ipo_time 弹窗从 State 1（TBD）跳转至 State 2 或 State 3，倒计时开始展示
② 填入 market_open_time 424B4 确认后 按 IPO 日期 + 约 2 个工作日计算正式开市时间，填入 market_open_time；同时核对并按需更新 ipo_time 系统准备好 State 5 的触发节点
③ 切换标题栏标签 market_open_time 到达后 手动将前端标题栏标签从橙色 Pre-IPO 切换为红色 IPO Merge 标题栏标签变为红色 IPO Merge，提示用户进入价格融合阶段
④ 切换 symbol_type 确认价格融合稳定后 将 symbol_type 从 PRE_IPO 切换为 US_STOCK（或 KR_STOCK） 所有 Pre-IPO 标签消失，弹窗关闭，合约按普通 TradFi Perp 规则展示
操作 ③ 和 ④ 均为手动触发，原因是需要人工确认股票已稳定上市、价格数据正常，避免因数据延迟造成用户端展示错误。
