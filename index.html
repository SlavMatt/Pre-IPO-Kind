Pre-Launch 交易阶段后端说明
1. Pre-Launch 概述
1.1 概述

Pre-Launch 永续合约允许用户在目标公司正式上市前进行交易。合约与平台现有 TradFi Perp 共享同一 perp 账户，使用 USDC 作为保证金和结算资产，采用 7×24 小时连续交易模式。

  • 保证金：USDC
  • 合约类型：永续
  • 交易时间：7×24 小时；与普通 TradFi Perp 不同，Pre-Launch 阶段不受现实市场开收盘时间限制，但不同阶段的风险等级和交易限制不同

Pre-Launch 阶段结束的标志是开发将 symbol_type 由 PRE_LAUNCH 切换为对应 country_stock 类型（如 US_STOCK），此后合约按普通 TradFi Perp 规则运行。

1.2 上市路径类型

不同的上市路径对应不同的前端弹窗文案和（部分情况下）不同的 State 逻辑。当前后端字段 listing_type 用于标识路径类型。

Symbol 标准

使用目标公司预期上市 ticker + -PERP（以路演和 S-1 / S-4 文件为准）。SPAC 使用目标公司 ticker，不用壳公司 ticker（壳公司与最终上市主体不同）。

Index 来源

Pre-Launch 阶段标的未在交易所上市，Index 价格综合参考已上线同标的合约的市场报价：

  • Hyperliquid（XYZ）为主要来源；若 XYZ 未上线，需至少参考 1 个主流 CEX
  • 辅助参考：OKX、Binance 等主流 CEX
listing_type路径名称SEC 文件关键时间字段本期支持
IPO传统 IPOS-1ipo_time + market_open✓
DLDirect ListingS-1market_open✓
SPACSPAC 合并S-4market_open✓
IPO 和 DL 流程基本相同，只有 SPAC 的上市逻辑上有一个股东投票的环节，会导致比其他两种更早退市。
* IPO 跟踪两个时间字段（定价 + 开市），中间约 12h–2 天为 Pre-Listing 中间态；DL / SPAC 只跟踪开市时间 market_open，无 Pre-Listing 中间态。
2. Pre-Launch 品类归属与交易时段
2.1 Pre-Launch 品类定义

Pre-Launch 合约在交易时段上属于 Crypto 24/7，是个股的特殊前置阶段，上市后自动归入该子类型的常规规则。

  • 不同子类型遵循不同的开收盘、冬夏令时、节假日规则
  • 本期只针对子类型配置 IANA 时区，不针对具体交易对单独配置
分类子类型例子本期IANA 时区
股票美股个股TSLAYAmerica/New_York
韩股个股SAMSUNGYAsia/Seoul
Pre-Launch（新增）Pre-Launch 永续合约SPCXYAmerica/New_York
Pre-Launch 的 IANA 时区应用场景：① ipo_time（Est. IPO Date）录入时区参考——仅 IPO 路径；② market_open（Market Opening）时间录入时区参考——三种路径通用。Pre-Launch 阶段本身 7×24 连续交易，不受时区开收盘影响。
2.2 Pre-Launch 交易时段与流动性预警处理

Pre-Launch 阶段不受现实市场开收盘时间限制，采用 7×24 连续交易，但不同 State 的流动性和交易限制不同。以下为 Pre-Launch 专属时段定义：

2.3 个股常规交易时段（Pre-Launch 结束后适用）

当开发将 symbol_type 切换为 COUNTRY_STOCK 后，合约退出 Pre-Launch 阶段，按美股 / 韩股个股常规时段规则运行，详见 1.0 TradFi 交易模块概述。

3. 核心字段配置

以下字段决定 Pre-Launch 弹窗的所有状态流转。前端实时读取这些字段计算当前 State，无本地缓存。

字段名类型说明写入方式
is_pre_ipoBoolean 是否处于 Pre-Launch 阶段。为 true 时前端展示弹窗入口标签及所有 Pre-Launch UI。 开发手动
listing_typeString 上市路径。取值：IPO / DL / SPAC。决定前端弹窗文案和 State 逻辑分支。 开发手动
ipo_timeTimestamp (UTC) 预计 IPO / 上市发生时间。路演开始时填入软确认日期；424B4 发布后如有变动需更新。未填写时弹窗展示 State 1（TBD）。 开发手动
market_open_timeTimestamp (UTC) IPO 后正式开市时间，通常为 IPO 日期后约 2 个工作日的 09:30 ET。触发 State 5 → State 6 的切换节点。 开发手动
target_iana_idString 目标上市市场的 IANA 时区，创建合约时预填。Pre-Launch 期间不生效（24/7 交易）；symbol_type 切换后自动激活。示例：美股 America/New_York，韩股 Asia/Seoul。 开发手动（合约创建时）
symbol_typeString Pre-Launch 阶段为 PRE_LAUNCH；IPO Merge 完成后切换为 US_STOCK 或 KR_STOCK，前端据此隐藏所有 Pre-Launch 标签，合约进入普通 TradFi Perp 逻辑。 开发手动

4.3 综合判断逻辑（优先级）

按以下顺序从上往下判断，命中第一条即确定当前 State，不继续向下匹配。IPO / DL / SPAC 三条路径共用第 1–2 步；第 3 步起按 listing_type 分支：

第 1 步
判断 is_pre_ipo 是否为 true → 否则不展示弹窗，退出
第 2 步
判断 State T：价格源（Hyperliquid / Binance 等）流动性枯竭，或 SPAC merge_status = terminated（投票失败），或收到开发手动终止信号 → State T，最高优先级，立即终止
第 3 步 · IPO
判断 current_time > market_open 且 symbol_type = PRE_LAUNCH → State 6（Market Merging）
第 4 步 · IPO
判断 ipo_time < current_time < market_open → State 5（Pre-Listing）
第 5 步 · IPO
判断 ipo_time 是否为空 → State 1（TBD）；否则计算剩余时长 → State 2 / 3 / 4
第 3 步 · DL / SPAC
判断 current_time > market_open 且 symbol_type = PRE_LAUNCH → State 5（Market Merging，DL/SPAC 无 Pre-Listing）
第 4 步 · DL / SPAC
判断 market_open 是否为空 → State 1（TBD）；否则计算 market_open - current_time → State 2 / 3 / 4

监听 SEC EDGAR 的 S-1/A 修订或 NASDAQ / NYSE 公告，发现日期变动后第一时间更新后台 ipo_time 字段。
第 2 步
前端倒计时基于 ipo_time 实时计算，更新后弹窗状态自动跳转——若新日期更远则从 State 4 退回 State 3 / 2；若更近则加速进入 State 4。
第 3 步
日期变更属于高风险操作，建议同步在平台向用户发出公告，避免因倒计时突变引发误操作。
6. 非活跃阶段开仓限制
6.1 Reduce-Only 触发方式（1.0 单交易对开关）

Pre-Launch 合约的 Reduce-Only 通过管理员手动配置单交易对 Reduce-Only 开关（1.0）实现，用户无法开新仓，仅允许平仓操作。不同路径配置如下：

IPO 路径（需配置两个阶段）
  • State 5（Pre-Listing，约 12h–2 天）：时间边界已知，可在确认 ipo_time 和 market_open 后预填开关的开始时间（= ipo_time）和结束时间（= market_open），提前排程生效。
  • State 6（Market Merging）：开始时间设为 market_open；结束时间未知，须等开发确认价格稳定、手动切换 symbol_type 后，再手动关闭开关解除 Reduce-Only。
Direct Listing 路径（只需配置一个阶段）
  • State 5（Market Merging）：开始时间设为 market_open；结束时间未知，须等开发手动切换 symbol_type 后关闭开关。
  • DL 无 Pre-Listing 中间态——State 4 倒计时结束后直接进入 Market Merging。
SPAC 路径（只需配置一个阶段）
  • State 5（Market Merging）：开始时间设为 market_open（合并完成时间）；结束时间未知，须等开发手动切换 symbol_type 后关闭开关。
  • SPAC 无 Pre-Listing 中间态——State 4 倒计时结束后直接进入 Market Merging。
6.2 管理员手动开关

极端市场情况下，管理员可通过全局开关对所有 TradFi 合约统一收紧，优先级高于单交易对开关。Pre-Launch 正常运营期间不使用此开关。所有开关仅影响 open order，平仓的 reduce 单不受限制。

开关类型影响范围适用场景
全局 Reduce-Only 开关 所有 TradFi 合约 极端市场情况下对整个 TradFi 品类统一收紧
单交易对 Reduce-Only 开关 指定合约（如 SPCX-PERP） Pre-Launch 场景优先使用，避免影响其他正常合约

8. 手动操作节点时序

以下节点均需开发人员在确认现实状态后手动触发，系统不自动执行，目的是避免数据延迟造成错误切换。

操作顺序触发时机操作内容前端变化
① 填入 ipo_time 路演开始时（IPO 前 1～2 周） 将路演公布的 IPO 日期（UTC）填入 ipo_time 弹窗从 State 1（TBD）跳转至 State 2 或 State 3，倒计时开始展示
② 填入 market_open_time 424B4 确认后 按 IPO 日期 + 约 2 个工作日计算正式开市时间，填入 market_open_time；同时核对并按需更新 ipo_time 系统准备好 State 5 的触发节点
③ 切换标题栏标签 market_open_time 到达后 手动将前端标题栏标签从橙色 Pre-IPO 切换为红色 IPO Merge 标题栏标签变为红色 IPO Merge，提示用户进入价格融合阶段
④ 切换 symbol_type 确认价格融合稳定后 将 symbol_type 从 PRE_LAUNCH 切换为 US_STOCK（或 KR_STOCK） 所有 Pre-Launch 标签消失，弹窗关闭，合约按普通 TradFi Perp 规则展示
操作 ③ 和 ④ 均为手动触发，原因是需要人工确认股票已稳定上市、价格数据正常，避免因数据延迟造成用户端展示错误。
